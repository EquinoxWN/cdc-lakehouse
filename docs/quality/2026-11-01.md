# Quality check, 2026-11-01

The owner's 10 rules, checked against the code on Windows 11 with Python 3.14.5. The Docker stack
is not run locally; the end-to-end path is checked by the `e2e` workflow.

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Assume every call can fail | fixed | Connect REST calls have a 10 s timeout (`connector.py` `_request`), registry GETs 10 s (`e2e.py` `_get_json`), Kafka admin `list_topics(timeout=5)`, consumer `poll(1.0)`. The Postgres connection in `e2e._make_changes` had no timeout: added `connect_timeout=10`. `wait_running` polls at a fixed interval inside a deadline (bounded); while Connect refuses connections it kept no trace of the error, so a timeout said only `{}`: it now reports the last error and chains it (`raise ... from last_err`). No `except: pass`; the two broad handlers re-raise (`e2e.main`) or record the problem in the report (`e2e._consume`). |
| 2 | Writes safe to retry | fixed | Connector registration is `PUT /connectors/<name>/config` (idempotent, test `test_register_puts_config_idempotently` sends it twice). `e2e._make_changes` inserted `grace@example.com` unconditionally, so a second run hit the `UNIQUE` email constraint: it now deletes that row first. `sql/init.sql` runs once, on an empty volume (Postgres entrypoint). |
| 3 | No race conditions | N/A | No shared mutable state: the library is pure functions plus one-shot HTTP calls; the test fake server's class lists are reset per test. |
| 4 | Don't trust the clock | pass, limitation | Deadlines use `time.monotonic()` (`connector.wait_running`, `e2e._wait_for_topic`, `e2e._consume`). Lag is consumer wall time minus the Postgres commit timestamp (`events.lag_ms`); a cross-system lag can only be measured on a shared clock, which holds in CI (one host). Stated in the README. `time.time()` in the consumer `group.id` is only a unique suffix. |
| 5 | Read before changing | fixed | `CONNECT_URL`, `REGISTRY_URL`, `KAFKA_BOOTSTRAP` and `PG_DSN` (`e2e.py:26-29`) were read but not documented: now listed in the README "Run it" section with their defaults. `psycopg.connect(connect_timeout=...)` is a libpq parameter accepted by psycopg 3.3.6. |
| 6 | Never break compatibility | pass | No schema, API or file-format change. Topic names, connector name and config keys unchanged. |
| 7 | One source of truth | fixed | The only cache, `e2e._schema` (`functools.cache`), now says why it cannot go stale: registry content ids are immutable and it lives for one process. Python versions agree (`requires-python >=3.11`, CI 3.12, README "3.11 or newer"). |
| 8 | Small changes, no secrets, validate input | pass | Secret grep: only local-stack defaults in `docker-compose.yml` (documented as throwaway in SECURITY.md) and `s3cret` in tests. Inputs: `connector_config` rejects a missing password and an empty table list, `http_url` refuses non-http(s) URLs, `wire.split` rejects short and wrong-magic frames, `from_envelope` rejects non-Debezium values. No new dependency. |
| 9 | Tests that can actually fail | fixed | No `assert True`, skips or xfails. Mutation check below: 4 of 18 mutants survived; each now has a killing test. |
