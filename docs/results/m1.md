## First CI run of the e2e workflow (2026-10-04)

The first `e2e` runs failed in the "End-to-end check" step. The most likely cause, found by review:
Apicurio's converters default to `apicurio.registry.headers.enabled=true`, which puts the schema id
in Kafka record headers and leaves the payload without the Confluent magic byte and id that
`wire.split` expects. The connector config now sets `headers.enabled=false` on both key and value
(asserted by `test_both_sides_use_avro_with_registry`), and the e2e check now lists any message it
cannot decode (error, first bytes, header names) in the job summary instead of stopping at the
first one. Record the next run's table here once it passes.
