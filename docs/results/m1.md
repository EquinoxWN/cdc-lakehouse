## How the e2e check was made to pass (2026-10-04 to 2026-10-06)

The `e2e` workflow failed on every run until three changes were made. CI logs need a signed-in
account to read, so the first two causes were found by reviewing the code; the check now also
publishes its report (and Connect's errors on failure) as run annotations, which anyone can read,
and the third cause was read from that report.

| # | What was seen | Cause | Fix |
|---|---|---|---|
| 1 | Failing "End-to-end check" step, no readable output | Found by review: Apicurio's converters put the schema id in Kafka record headers by default, so payloads lack the Confluent magic byte and id | `apicurio.registry.headers.enabled=false` on key and value, asserted by `test_both_sides_use_avro_with_registry` |
| 2 | Still failing after fix 1, no readable output | Found by review: the consumer subscribed before the snapshot had created the topic, and librdkafka only rechecks a missing topic every 5 minutes, longer than the 120 s budget | Wait until the topic exists, and refresh topic metadata every 2 s |
| 3 | First readable report: connector RUNNING, 7 schemas, 6 messages received, all failing with `UnknownType: io.debezium.connector.postgresql.Source` | The converter registers each nested named type as its own artifact and stores the envelope with references to them | `registry.load_schema` defines every referenced type before parsing; 4 tests with a fake registry. The next run passed |

Fixes 1 and 2 were not confirmed one by one; the run after fix 3 shows the three together work.
