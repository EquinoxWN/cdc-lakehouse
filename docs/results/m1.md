## Verified in CI (`e2e` workflow)

`python -m cdc_lakehouse.e2e` registers the connector, then inserts, updates and deletes
customers, consumes `shop.public.customers` from Kafka, decodes each message with the schema
fetched from the registry, and fails unless all of this holds:

| Check | Pass condition |
|---|---|
| Connector and task | RUNNING |
| Snapshot of the 2 seed customers | 2 `snapshot` events |
| Live changes | at least 2 `insert`, 1 `update`, 1 `delete` |
| Schemas | at least one Avro artifact registered |
| Lag | p50 and p95 commit-to-consumer lag reported in the job summary |
